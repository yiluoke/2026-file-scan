## 自動テスト

```sh
set -a
source .env
set +a
python scripts/test_postgres.py
ruff check src scripts tests
git diff --check
```

- 全156テスト成功（32.44秒、スキップなし）。PostgreSQL 18.6・pgvector 0.8.6を使用。
- ruff・差分の空白検査も成功。
- Docling/Pydantic由来の既存非推奨警告5件。テスト失敗なし。
- 実PostgreSQLのテストは専用DB内に一時schemaを作成し、終了後に削除する。SQLiteはDB非依存部分の単体テストに残す。
- OpenAIはSDKのHTTP層を模擬する。実APIへの接続・課金は行っていない。

| 改善 | 確認した条件と結果 |
| --- | --- |
| 選択世代 | A成功→B失敗でAに戻らない。A→B→AでAを選択。別設定でembedすると設定不一致を明示 |
| 表・トークン分割 | Docling形式の長い表を分割しても全チャンクに列見出しが入り、原本文字範囲が一致。長い日本語・絵文字・見出しと最小文脈予算でも全入力が上限内 |
| 段階別キャッシュ | 分割変更で再抽出せず、同じ入力のAPI再呼び出しも不要。v2保存済みベクトルも再利用。次元変更は別プロファイル |
| 解析再利用 | 同じワーカーを使い、タスク数上限で交換。期限超過ワーカーを停止し、次文書を処理可能。実PDF2件でConverter再利用を確認 |
| 読込・送信バッチ | 12文書を3件ずつ読み出し、2件以下で送信。API処理時は読込・保存用DB接続なし。合計8191トークンの要求上限も検証 |
| モデル整合性 | 固定版・配置済み実モデルの検査成功。別の一時模擬モデルを同サイズで改変／削除すると検査失敗。非PDFはモデル配置に依存しない |
| 状態・履歴 | 全文書を除外すると現在件数は0、現在世代は空、過去の成功世代は履歴集計へ残る |

| DB移行 | v1/v2→v3の非破壊移行・再実行・履歴保持を検証。移行時には過去世代を自動選択せず、次回ingestで選択を確定 |

## 公開原本と実モデル

公開済みTXT・Word・Excel・PDF各2件、計8原本を既取得のSHA-256と照合し、原本非変更、本文・位置・登録・再実行を確認した。PDFはDocling 2.140.0の実レイアウトモデル・TableFormer accurateをCPUで実行し、表セル・bbox・ページ番号を検査した。OCR待ち画像の保持と部分抽出も生成PDFで確認した。

公開原本の由来とハッシュは[public-samples.json](../../examples/public-samples.json)、モデルの固定版は[docling-models.lock.json](../../src/file_scan/docling-models.lock.json)に記録する。

## 開発用DBでの確認

既存の`file_scan`を`init-db`でv3へ移行した。原本・過去世代は保持し、新しい仕様で公開8原本すべてを成功登録した。最初の実解析では1プロセスを起動して7回再利用し、記録されたピークメモリは1248.1 MiB。次の取り込みは8件ともunchanged、解析プロセス起動0、原本の一時書込み0バイト。

さらに分割実装の更新後は8件とも抽出キャッシュを使って新世代を作り、解析プロセス起動0を確認した。原本は毎回188534バイトを完全ハッシュ照合しており、共有元の読込自体を省略したという意味ではない。モデルの`--verify-only`も成功した。

`status`は現在の文書8・選択世代成功8と履歴を分離する。開発設定は引き続き仮キー・`embedding.enabled=false`で、embedはdisabled。未生成の73チャンクはpendingと表示する。模擬ベクトルを開発用DBへ保存しない。

実行記録は`artifacts/reports/ingest-*.json`と`ingestion-improvements-validation.json`に保存する。共有サーバーの変更通知・ネットワーク性能、Windows実機、本物のAPIキーによる品質・料金、検索APIは今回の検証範囲に含めない。速度向上率の比較測定は行っていない。

最終実行：`37376432-d73b-4455-b29a-e4dea27f700d`は8件を抽出キャッシュから新世代へ登録し、`5f5038e3-bc45-47e8-9a1b-8e3f6c8ac007`は8件unchanged。両実行とも原本一時書込み0、解析プロセス起動0。
