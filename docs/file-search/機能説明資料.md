# 検索APIの機能説明資料

[機能別ドキュメント一覧](../README.md)

保守担当者が「日次締めで E1203 が出たとき、どの手順を確認すればよいか」と調べる場面を例に説明します。検索APIは、公開済みの資料から関連する文章と出典を返します。担当者はその箇所を原本で確かめられます。Difyで回答を組み立てる場合も、同じ根拠を利用できます。

## 資料が検索できるようになるまで

```mermaid
flowchart LR
    A["文書・生成仕様書"] --> B["取込担当者が下書きを確認"]
    B --> C["検索用ベクトルを生成"]
    C --> D["公開担当者が業務版と世代を指定"]
    D --> E["検索APIが公開コピーを参照"]
    E --> F["本文・出典・準備状況"]
```

たとえば、運用手順書と障害対応表があるとします。取込担当者は、手順書から抽出した段落や、対応表のシート名・セル範囲を確認します。公開担当者は、採用する世代を選び、対象の業務版に公開します。この時点でどの内容を採用したかが固定されます。

手順書が改訂され、取込で新版が確定すると、その文書の古い公開コピーは現行版の検索対象から外れます。他に公開済みの資料があれば、その資料から根拠が返ることがあります。改訂後の内容を確認して再公開すると、新しい手順書が現行版の検索対象に戻ります。緊急に資料を取り下げるときは、公開担当者が該当する業務版で公開を取り消します。[版の作成と公開](仕様書.md#版の作成と公開) ／ [公開の取り消し](仕様書.md#公開の取り消し)

## どの文章が選ばれるか

| 探し方 | 「日次締めで E1203」という質問で拾いやすい箇所 |
| --- | --- |
| 意味の近さ | 質問とは異なる言い回しで「締め処理を再実行する条件」を説明した段落 |
| 全文検索 | 本文に「日次締め」と記載された手順や説明 |
| 識別子の一致 | エラーコード `E1203` を含む障害対応表の行 |

APIはそれぞれの順位を合わせて候補を選びます。スコアは候補を並べるための値です。上位の候補でも、別の画面や業務の手順が混じる場合があるため、資料名と適用版を一緒に確認してください。見出しや表の列名を補ったレコードでは、`evidence_role` が `context` になります。どのヒットを補ったかも応答からたどれます。

## 根拠を原本で確かめる

1. 検索結果の `title` と `content` を読み、調査対象と関係する箇所を選びます。
2. `metadata.source_locations` を確認します。Excelならシート・セル範囲、PDFならページなど、形式に応じて記録された位置を使います。
3. `metadata.source_ref` を検索APIのベースURLにつなぎ、検索と同じ接続キーで原本を取得します。対応する画像があれば、`related_assets[].image_ref` から取得できます。画像説明などの派生情報を使う場合は、原図と照合します。

C++・Qtソースから生成した資料の場合、ここで開く原本は公開したMarkdownです。実装まで確かめたいときは、Markdown内の根拠に記されたソースファイルと行を確認します。[C++・Qtソース取込の機能説明資料](../cpp-scan/機能説明資料.md)

## 検索結果が少ないとき

状態付き検索は「質問に合う根拠が返ったか」と「対象の業務版に必要な資料がそろっているか」を別々に返します。次は結果の読み方の例です。

| 資料の準備状況 | 質問に対する結果 | 読み方と次の操作 |
| --- | --- | --- |
| `complete` | `matched` | 対象範囲の準備が完了し、根拠が見つかりました。本文と原本位置を確認します。 |
| `complete` | `no_match` | 今回の条件で返せる根拠はありません。エラーコードの表記・質問・絞り込み条件を見直します。 |
| `incomplete` | `matched` または `no_match` | 未公開・更新待ち・部分抽出・ベクトル不足などがあります。公開担当者は状態の件数を見て、該当文書を確認します。 |
| `unknown` | 任意 | 収集状態や版との対応が確定していません。棚卸し結果と対象の業務版を確認します。 |
| 任意 | `budget_exhausted` | 返却上限内に根拠を収められませんでした。質問や対象資料を絞って再検索します。 |

たとえば、障害対応表が見つかっても、改訂中の運用手順書が再公開待ちであれば `incomplete` と `matched` は両立します。この場合は、見つかった対応表を出典として示し、運用手順書の更新状況も回答に添えます。

## Difyや業務画面から利用する

準備状況まで画面に表示する場合は `POST /search-with-status` を使います。Difyの標準External Knowledge連携は `POST /retrieval` を使い、準備不足や返却予算不足ではHTTP 409を返します。通常モードと接続試験用の固定応答は `execution_mode` で判別できます。接続キーを共有する利用者は同じナレッジの公開資料を参照できるため、公開担当者が資料の共有範囲を確認します。[入力と応答の仕様](仕様書.md#入力) ／ [Dify接続と受入確認](本番導入仕様.md#dify)
